# 1. What Is JVM?

**JVM (Java Virtual Machine)** is an abstract machine that executes **JVM bytecode**.

It is a part of the Java platform that allows compiled Java programs to run on different operating systems and hardware.

## The key definition

> **JVM is an abstract machine defined by the Java Virtual Machine Specification that executes JVM bytecode and provides the runtime model required for Java and other JVM languages.**
## The basic idea

Java source code is not compiled directly into machine code.

Instead:

```text
Java source code
       ↓
     javac
       ↓
JVM bytecode (.class)
       ↓
      JVM
       ↓
Machine code
       ↓
     CPU
```

For example:

```java
int result = 10 + 20;
```

is compiled into JVM bytecode. The JVM then executes that bytecode.

## Why is it called a Virtual Machine?

The JVM defines an **abstract computer** with its own:

- instruction set
    
- memory model
    
- execution model
    
- type system
    

This computer does not physically exist.

The actual JVM implementation translates or executes these abstract instructions using the real operating system and CPU.

```text
              JVM
       ┌───────────────┐
       │ JVM bytecode  │
       │ memory model  │
       │ instructions  │
       └───────┬───────┘
               ↓
        Operating System
               ↓
              CPU
```

Therefore, the JVM creates an abstraction layer between the Java program and the underlying hardware.

## JVM and platform independence

The important point is:

> **The bytecode is platform-independent, while the JVM implementation is platform-specific.**

The same `.class` file can theoretically be executed on different platforms:

```text
                  Main.class
                      │
          ┌───────────┼───────────┐
          ↓           ↓           ↓
      Windows JVM  Linux JVM  macOS JVM
          ↓           ↓           ↓
         CPU         CPU         CPU
```

Each platform needs a JVM implementation appropriate for that platform.

This is what makes the **"Write Once, Run Anywhere"** model possible.

## JVM is not Java

These concepts are different:

```text
Java
→ programming language

Bytecode
→ compiled instructions for the JVM

JVM
→ abstract machine that executes bytecode
```

Java source:

```text
.java
```

Compiled Java:

```text
.class
```

The `.class` file contains JVM bytecode.

## JVM is not HotSpot

**JVM** is defined by the **Java Virtual Machine Specification**.

**HotSpot** is one concrete implementation of that specification.

Other JVM implementations exist as well.

```text
JVM Specification
       │
       ├── HotSpot
       ├── OpenJ9
       └── other implementations
```

The specification defines **what the JVM must do**, while an implementation determines **how it does it**.
### Remember

```text
Java       → language
.class     → JVM bytecode
JVM        → executes bytecode
HotSpot    → JVM implementation
```
